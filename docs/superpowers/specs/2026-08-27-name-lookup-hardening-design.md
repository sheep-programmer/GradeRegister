# 点名加固：号码定位 · 重复折叠 · 歧义询问

日期：2026-08-27

## 背景

一段真实录音里 8 次点名有 4 次听错，全靠拼音纠正救回来（五米→吴敏、正好→郑浩、刘阳→刘洋、浏洋→刘洋），另有一次「李四李四李四」重复幻听。同一段录音里的分数识别几乎没错过——数字比人名好认得多。

点名是整个流程错误率最高的环节。这一轮不改录入方式（点名保留），只加固点名本身。

## 不做的事

- **语音命令**（撤销／删除／保存／核对）：不做。改分靠重说一遍，这条路已经可用：带题号（「第二题85分」）或带表头名（「程序题90分」）都会覆盖旧分并记为修正。
- **顺序录入模式**：不做，点名保留。
- **朗读回执**：不做。

## 一、号码定位

念号码和念名字两条路都通，号码来源自动适配表格：

| 表格情况 | 号码含义 |
|----------|----------|
| 有学号／座号／编号／考号／序号列 | 该列的真实值 |
| 没有这类列 | 名单序号，第几位就是几号 |

### 结构识别

`identify_columns` 增加返回 `id_col`，按表头关键词识别；找不到置 -1。`SheetModel` 增加 `id_col` 字段，`StudentRecord` 增加 `sid`（学号原文，无学号列时为空）。`load_sheet` 读入该列的值。

学号列不会被误当题目列：题目列要求表头含「题」或纯数字，「学号」两者都不是。学号列在姓名列之前（学号／姓名／第一题…）也不影响姓名列识别——姓名列按关键词匹配。

### 号码必须带标记词

不带标记的裸数字一律当分数，否则「78」是学号还是分数无法区分。

| 念法 | 结果 |
|------|------|
| `5号` `五号` `学号5` `座号5` | 号码 5 |
| `第五个` `第5个` | 名单第 5 位 |
| `5号78分85分` | 定位 5 号，再填 78、85 |
| `5分` | 分数 |
| `第三题` | 题号 |
| `78` | 分数 |

`parser` 新增 `extract_student_id(text) -> (号码文字 | None, 去掉号码后的剩余文本)`。

### 匹配顺序

`state.select_student` 先试号码：号码命中唯一学生就直接激活，剩余文本交给填分逻辑。号码没命中（超出名单范围）则报错，不退回姓名匹配——念了「20号」而班上只有 12 人是明确的错误，猜名字只会填错人。

文本里没有号码标记时，走原有姓名匹配。

## 二、重复折叠

`李四李四李四` → `李四`。整段文本是同一个词重复 N≥2 次时折叠成一次；`张三张三丰` 不是整段重复，不动。

`parser` 新增 `collapse_repeats(text)`，在 `handle_text` 最前面做。

## 三、拿不准就问（修一个真实缺陷）

现状：`handle_text` 里 `correct_names_in_text` 在拼音纠正阶段就硬选最高分的名字并改写文本。后面的 `match_student_names` 拿到的已是确定名字，于是走精确匹配分支——**现有的候选弹窗机制永远不会触发**，即使班上同时有「刘洋」和「刘阳」也是闷头猜一个。

改法：`best_name_by_pinyin` 同时给出次佳分数。最佳与次佳差距小于 `_NAME_AMBIGUOUS_GAP` 时**不改写**文本，让原文进入 `match_student_names` 的模糊匹配，自然返回多个候选 → `select_choices` → 弹候选框。候选框已支持点选，本轮补语音说「第一个」「第二个」选择。

## 四、已录完的降权

老师很少回头重录，但确实会回头改分，所以只做裁决不做排除：`best_name_by_pinyin` 接受一个 `prefer` 集合（未录完的学生），仅在两名候选拼音分数接近时优先未录完的那个。分数差距明显时该谁就是谁，改分照样点得到人。

## 五、提示语收尾

各题填满后不带题号重说会被拒绝（安全，不猜位置），但提示语写死「例如「第三题九分」」。表头是「程序题」时应举表头名的例子。

## 测试

- 号码定位：有／无学号列两种表、号码超范围报错不猜名字、`5号78分` 一句连念
- 标记词边界：`5分` 不是号码、`第三题` 不是号码、裸数字不是号码
- 重复折叠：整段重复折叠、`张三张三丰` 不动
- 歧义：班上同时有刘洋与刘阳时弹候选框而非猜一个；差距明显时不弹
- 降权：不影响已录完学生的改分
- 提示语举例用表头名
