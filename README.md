# 成绩登记系统

面向中小学老师的语音成绩录入工具。打开成绩 Excel，念学生姓名自动定位到对应行，念各题得分自动填入，总分自动计算；再念一遍自己心算的总分与软件核对，不一致就标红。

**语音识别全程在本机完成，录音数据不出本机，录完不联网也能用。** 支持 macOS 与 Windows。

```
念「张三」            → 表格跳到张三那一行，行号与列头亮起
念「第一题十八分」     → 18 填进第一题，格子标黄
念「第二题十二分」     → 12 填进第二题
念「总分三十」        → 与软件算出的 30 一致，核对列写 ✓，自动写回 Excel
念「下一个」          → 跳到下一位还没录完的学生
```

---

## 为什么这样设计

### 核对是这个工具的核心，不是附加功能

语音识别不可能百分之百正确。与其追求「一次就对」，不如让**错误必然被发现**：老师自己心算一个总分念出来，软件把听到的各题相加，两个数一对，对不上就标红。

```
不一致（报90 算100）
```

核对列里连你报的数一起写出来，差多少一眼看得见 —— 只写「不一致」的话还得回头自己算一遍。核对通过才写回 Excel（默认），所以文件里的每一行都是对过的。

### 分不清就问，绝不替你猜

发音撞车的地方很多：两个「张三」、「刘洋／刘阳」、「掌声」同时像「张三」和「张伟」。

这些情况一律**弹窗让你点**，而不是挑一个相似度最高的填下去。选人期间还会**暂停听写** —— 老师挑人时常自言自语，那些话不该被当成指令。选完之后，暂存的那句分数会自动补上，不用重念。

判断依据是拼音相似度的**头名与次名差距**，不是绝对分数：差距太小说明分不出来，就该问。

### 只在能确定的地方自动，不确定就明确报错

- 念「20 号」而班上只有 12 人 → **明确报错**，不去猜最接近的那个
- 题号超出范围（只有 4 题却念了第八题）→ 忽略并说明
- 数字大到不可能是分数（识别把数字连成了 `99999999`）→ 拒绝并说明
- 各题都填满了还念一个不带题号的分数 → 提示补念题号，绝不猜位置

宁可让老师多说一句，也不让一个错分数悄悄进表。

### 同音误听在解析层就纠回来

语音识别把「十八分」听成「时八分」、「七分」听成「气氛」、「三分」听成「三粉」是常态。这些不靠换模型解决，靠一张从实际使用日志里长出来的同音表和拼音纠错：

| 听到 | 纠正为 | 靠什么 |
|---|---|---|
| 时八分 | 18 分 | 同音字表 |
| 气氛 / 三粉 | 7 分 / 3 分 | 同音字表 |
| 第一体 / 第一期 | 第一题 | 题号后缀容错 |
| 掌声 | 张三 | 拼音相似度 |
| 成序题 | 程序题 | 表头拼音纠错 |
| 钟分九十 | 总分 90 | 关键词拼音兜底 |

拼音纠错有一条硬边界：**叠字不纠**。噪声和口吃折叠后就是「第第」这类叠字，而叠字的两个音节完全相同，跟任何「声母不同、韵母相同」的姓名都算得很像（didi 对 lisi 有 0.65），而真实误听最低只有 0.58 —— 两段区间重叠，调阈值分不开，只能按结构挡掉。

### 你的原始表格是安全的

- 首次打开自动备份到 `backups/`，保留最近 20 份
- 只写分数、总分、核对三列，**从不改动姓名和其他任何内容**
- 表头不必在第一行（上方可以有标题行），总分列不必在最右边
- 写回时保留原文件的格式；写不进去（Excel 占着文件）会**明确报错**，不会静默丢分数
- 退出前如果存不下，会问你要重试、放弃还是留在程序里，而不是一声不响地关掉

### 两边不抢同一个文件

同时开着软件和 Excel 必然互相覆盖：Windows 上 Excel 独占锁文件，软件一次也写不进去；macOS 上写得进去，但 Excel 不重新读盘，它一保存就把分数全盖掉。

所以打开表格前会检测 Excel 是否占着它，并请 Excel **只关掉这一个工作簿**（你在里面没保存的改动会先存下来），Excel 里其他文件一概不动 —— 杀进程会连老师正在编辑的别的文件一起丢。

## 功能

| 场景 | 怎么念 | 行为 |
|---|---|---|
| 定位学生 | 「张三」 | 跳到该行；同名或同音会弹窗让你点选 |
| 按号码定位 | 「5号」「第五个」 | 有学号列按学号，否则按名单第几位；号码不存在明确报错 |
| 填分数 | 「第一题十八分」 | 按题号填；也可以直接念表头，「程序题72分」一样填得进 |
| 一口气念完 | 「第一题十分第二题二十分第三题三十分」 | 一句话填完整行 |
| 名字带分数 | 「孙丽第一题十分…总分一百」 | 一句话切人、填分、核对全做完 |
| 不带题号 | 「18分」「10加5加5」 | 顺序填入下一个空题 |
| 小数 | 「第一题十二点五分」 | 12.5 |
| 念错重填 | 对同一题再念一次 | 直接覆盖，可撤销 |
| 总分核对 | 「总分62」「一共62分」 | 一致写 ✓；不一致标红并写出你报的数 |
| 切下一位 | 「下一个」「下一位」「继续」 | 跳到下一位还没录完的学生 |
| 手动兜底 | — | 双击改分；右键清除单格／整行／整列／全部；Delete 清除选区 |

界面上**当前学生整行**浅黄、**行号与当前题目的列头**深黄、**行列交叉那一格**深黄 —— 照 Excel 的做法只标位置，不给别的学生的分数染色。

## 安装

### 方式一：下载现成的程序（推荐）

到 [发行版](../../releases) 页面下载，**不用装 Python、不用装依赖、不用联网**，默认语音模型已经打进程序：

- **Windows**：下载 zip，解压后双击文件夹里的 `GradeRegister.exe`
- **macOS**：下载 dmg，拖进「应用程序」。首次打开右键点图标 →「打开」→ 再点「打开」（没有苹果开发者签名）

首次录音时系统会问麦克风权限，**必须点允许**。

### 方式二：从源码运行

需要 **Python 3.9+**（含 tkinter）。

**macOS** 双击 `启动.command`，**Windows** 双击 `启动.bat` —— 首次运行会自动建虚拟环境、装依赖、下载模型。

手动安装：

```bash
pip install -r requirements.txt
python download_model.py        # 下载语音模型（默认约 228MB）
python main.py --check          # 环境自检
python main.py                  # 启动
python main.py 成绩表.xlsx      # 启动并直接打开某份表格
```

> macOS 若提示缺少 tkinter：`brew install python-tk@3.12`
> Windows 用 python.org 官方安装包自带 tkinter，无需额外操作

## 使用

1. **打开表格** —— 点右上角「打开表格」选 `.xlsx`。程序自动识别姓名列、题号列、总分列，并在总分列右边补一列「核对」。
2. **念姓名** —— 点「开始说话」进入连续听写，念「张三」，稍停即自动跳到该行。
3. **念分数** —— 「第一题十八分」「第二题十二分」，或者「18加12加15」。填到哪一题，那一格标黄。
4. **核对总分** —— 念「总分62」。一致写 ✓ 并写回文件；不一致标红，可撤销重录。
5. **切下一位** —— 念「下一个」，或在设置里开「录完自动切下一位」。

设置里可以改成**按住说话**（按住按钮或空格，松手识别），适合环境嘈杂、不想让软件一直听着的场合。

### 表格格式

第一行（或标题行之下的那一行）是表头：

| 姓名 | 第一题 | 第二题 | 第三题 | 第四题 | 总分 |
|---|---|---|---|---|---|
| 张三 | 18 | 12 | 15 | 17 | =SUM(...) |

识别规则：

- **姓名列** —— 表头含「姓名/名字/学生」，找不到则用第一列
- **题号列** —— 表头含「题」或纯数字；找不到就取姓名列与总分列之间的所有列
- **总分列** —— 表头含「总分/总成绩/总计/合计」，找不到则用最后一列
- **核对列** —— 总分列之后表头含「核对/核查/复核/检查/确认」的列，没有就自动新建
- **学号列** —— 表头含「学号/座号/编号/考号/序号」

只支持 `.xlsx`；老版 `.xls` 请在 Excel/WPS 里另存为 `.xlsx`。运行 `python make_instance.py` 可生成一张空的实例表（内含两位「张三」演示重名确认）。

## 设置

点右上角「设置」，保存到 `config.json`。

| 配置项 | 说明 |
|---|---|
| 识别引擎 | `sense-voice`（默认，整句解码，最准，随程序分发）/ `paraformer`（短句更快，对「姓名+分数」连读不丢字，约 217MB）/ `sherpa`（边说边出字，学生名单自动写进热词）/ `vosk`（模型仅 42MB）/ `faster-whisper`（慢，需 `pip install faster-whisper`） |
| 模型目录 | 引擎下面写着当前模型在哪。随程序分发的那份是只读的；要下载的引擎可以点「选择…」换个目录，**下载与读取都用它**。留空＝自动 |
| 麦克风 | 默认「自动选择」，每次启动挑一个真正收得到声音的设备 |
| 断句停顿 | 说完一句停顿多久算说完；`sherpa` 自带端点检测，这一项对它不起作用（面板里会置灰） |
| 剥离题号前缀 | 念「第一题18分」时只取 18 |
| 剥离「分」后缀 | **建议别关**：关掉后连念「3分4分5分」只会取到最后一个 |
| 总分写 =SUM() 公式 | 关闭则写算好的数值 |
| 核对一致时写 ✓ | 关闭则只标不一致 |
| 自动保存 | 四选一：**总分核对通过才存**（默认）/ 每填一个分数就存 / 每录完一名学生存 / 只在点「保存」时写盘 |
| 录完自动切下一位 | 核对一致后自动选中下一位未录完的学生 |
| 按住说话 | 默认关闭（点一下开始、再点一下结束） |
| 提示音 | 默认关闭。开了之后填分／核对通过／核对不一致／没听清各有不同的声音 |

模型从 huggingface 下载，访问慢或不通时**自动改用镜像**；有自建镜像可设环境变量 `HF_ENDPOINT`。

## 架构

分层清楚、依赖单向，所以核心逻辑可以脱离麦克风和界面测试：

```
录音线程                     主线程
──────────                   ──────────
recorder.py                  ui/main_window.py
  自动增益 / 自适应门槛 / 断句      表格渲染、十字高亮、右键菜单
      │                              │
      │ 音频块                       │ 识别文本
      ▼                              ▼
speech.py                      state.py
  引擎（本地模型）                 状态机：选人 → 填分 → 核对
      │                              │
      │ 文本  ──── 事件队列 ────►     │
                                     ▼
                               parser.py         excel_io.py
                                 中文数字、分数提取     结构识别、写回、备份
                                 姓名匹配、拼音纠错
```

| 模块 | 职责 | 为什么单独一层 |
|---|---|---|
| `parser.py` | 中文数字、分数提取、姓名匹配、拼音纠错 | 纯函数，不碰 IO。整套同音表与阈值都在这里，可以用文本直接测 |
| `state.py` | 状态机：`idle → scoring → total` | 不依赖 tkinter。语音与键盘走同一个 `handle_text()` 入口 |
| `excel_io.py` | 表结构识别、写回、备份 | 不知道语音的存在。畸形表格的容错都收在这里 |
| `recorder.py` | 录音线程、增益、断句 | 不依赖 tkinter，可以用假引擎单独测线程行为 |
| `speech.py` | 引擎适配（5 个引擎同一套接口） | 换引擎不影响上层：`begin/feed/finalize` 三个方法 |
| `platform_support.py` | 平台差异集中收口 | 界面代码不直接调 `os.startfile`、不写死字体名、不假设右键键号 |
| `ui/` | 主窗口、弹窗、控件、主题 | 设计令牌集中在 `theme.py`，控件不写死色值 |

几处关键设计：

**录音线程与主线程只通过事件队列通信。** 引擎不是线程安全的，串行化由录音器保证（压力测试 100 轮启停，引擎调用峰值并发始终为 1）。音量事件在主线程一轮里只画最后一个 —— 每条都重绘会在积压时冻住界面。

**平台差异不散落在界面里。** 右键键号（Tk 9 在 macOS 上从 Button-2 改成了 Button-3）、DPI 感知、中文字体候选、控制台编码、让 Excel 交出文件，全部收在 `platform_support.py`，各自都有针对性的测试。

**语音链路上最热的一段被缓存。** 拼音转换与相似度是纯函数，同一份名单在整节课里反复比对；缓存后单句从 24.1ms 降到 0.19ms，状态机整体 0.12ms/句 —— 相对语音解码的几百毫秒完全可忽略。

## 开发

```bash
python -m unittest discover tests        # 全部测试
python -m unittest tests.test_accuracy   # 准确率语料
```

界面冒烟测试需要图形环境，无头环境自动跳过。

**准确率语料**（`tests/test_accuracy.py`）是一批老师真实会念的话配上表格该变成什么，覆盖选人、填分、同音误听、核对、连说、切换、噪声、歧义八类。它测的是「文字 → 表格」这一段，不含语音识别本身。加新用例只需往 `CASES` 里追加一行。

发版：推一个 `v` 开头的 tag，GitHub Actions 会在 Windows 与 macOS 上各打一个包并建 Release。手动触发只打包不发版，用来验证流水线。

```bash
git tag v1.0.0 && git push origin v1.0.0
```

## 常见问题

**念了名字没反应** —— 先看左下角是否显示「已就绪」。说话前后各留半秒，太短会识别为空。

**名字识别不准** —— 弹窗会列出发音相近的候选，点选即可；也可以双击单元格直接打字。名单里有生僻字时，`sherpa` 引擎会把学生名单写进热词，念姓名更准。

**分数填错了** —— 对同一题重念一次直接覆盖；或点「撤销」（⌘Z / Ctrl+Z）；或右键该行「清除整行分数」。

**总分不一致** —— 软件把听到的各题相加与你报的总分对不上，说明有题念错或听错。核对列已写出两个数，差多少一眼看得见。

**完全没有声音** —— 点「帮助 → 麦克风没声音？」，里面按当前系统给出权限设置步骤，并可一键跳转到系统设置页。

**保存失败** —— 表格正被 Excel 打开时无法写入。打开表格前程序会尝试请 Excel 交出这份文件；如果关不掉，会让你手动关掉再重试。

**想边开 Excel 边录** —— 不建议。Excel 不会自动重新读盘，它一保存就用旧数据盖掉软件写入的分数；Windows 上更是直接锁死文件。录完再看。
