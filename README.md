# 成绩登记系统

语音驱动的试卷登分工具，面向中小学教师。打开成绩表，念出学生姓名与各题得分即可完成填写；再念一遍自己心算的总分，程序将其与自动求和的结果比对，不一致立即标出。

语音识别全程在本机离线完成，录音数据不上传、不联网。支持 macOS 与 Windows。

```
念「张三」             表格跳到张三所在行，行号与列头亮起
念「第一题十八分」      18 填入第一题，单元格标黄
念「第二题十二分」      12 填入第二题
念「总分三十」          与程序算得的 30 一致，核对列写入 ✓，并写回 Excel
念「下一个」            切换到下一位尚未录完的学生
```

## 核心特性

| 场景 | 语音指令 | 行为 |
|---|---|---|
| 定位学生 | 「张三」 | 跳转到该行；重名或同音时弹窗确认 |
| 按号码定位 | 「5号」「第五个」 | 有学号列时按学号，否则按名单顺序；号码不存在则报错 |
| 填写分数 | 「第一题十八分」 | 按题号填入；直接念表头（如「程序题72分」）同样有效 |
| 整行连报 | 「第一题十分第二题二十分第三题三十分」 | 一句话填完整行 |
| 姓名与分数连报 | 「孙丽第一题十分…总分一百」 | 一句话完成切换、填分与核对 |
| 省略题号 | 「18分」「10加5加5」 | 顺序填入下一个空题 |
| 小数分值 | 「第一题十二点五分」 | 填入 12.5 |
| 修正分数 | 对同一题重念一次 | 覆盖原值，可撤销 |
| 总分核对 | 「总分62」「一共62分」 | 一致则写入 ✓，不一致则标红并记录所报数值 |
| 切换学生 | 「下一个」「下一位」「继续」 | 切换到下一位尚未录完的学生 |
| 手动修正 | 无需语音 | 双击改分；右键清除单元格、整行、整列或全表；Delete 清除选区 |

录入过程中，当前学生所在行以浅黄底色标示，行号与当前题目的列头以深黄标示，两者交叉的单元格同样加深。高亮仅指示位置，不改变其他学生的分数显示。

## 安装

### 下载发行版（推荐）

在 [Releases](../../releases) 页面下载对应平台的安装包。无需安装 Python、无需配置依赖、无需联网，默认语音模型已随程序分发。

- **Windows**：下载 zip 包，解压后运行其中的 `GradeRegister.exe`
- **macOS**：下载 dmg，拖入「应用程序」。首次启动需右键点击图标并选择「打开」，再次确认后即可运行（程序未经苹果开发者签名）

首次录音时系统会请求麦克风权限，须选择允许。

### 从源码运行

要求 Python 3.9 及以上版本，且包含 tkinter。

macOS 运行 `启动.command`，Windows 运行 `启动.bat`。首次执行将自动创建虚拟环境、安装依赖并下载语音模型。

手动安装：

```bash
pip install -r requirements.txt
python download_model.py        # 下载语音模型（默认引擎约 228 MB）
python main.py --check          # 环境自检
python main.py                  # 启动
python main.py 成绩表.xlsx      # 启动并打开指定表格
```

macOS 若提示缺少 tkinter，执行 `brew install python-tk@3.12`。Windows 使用 python.org 官方安装包时已自带 tkinter，无需额外操作。

## 使用

1. **打开表格。** 点击右上角「打开表格」并选择 `.xlsx` 文件。程序自动识别姓名列、题号列与总分列，并在总分列右侧补充一列「核对」。
2. **念出姓名。** 点击「开始说话」进入连续听写，念出姓名后稍作停顿，表格随即跳转到该行。
3. **念出分数。** 依次报出「第一题十八分」「第二题十二分」，或连续报「18加12加15」。当前填入的单元格以黄色标示。
4. **核对总分。** 念出「总分62」。一致时写入 ✓ 并保存到文件；不一致时标红，可撤销后重录。
5. **切换学生。** 念出「下一个」，或在设置中启用自动切换。

设置中可切换为按住说话模式（按住按钮或空格键，松手后识别），适用于环境嘈杂或不希望程序持续监听的场合。

## 表格格式

表头位于第一行，或位于标题行之下的那一行：

| 姓名 | 第一题 | 第二题 | 第三题 | 第四题 | 总分 |
|---|---|---|---|---|---|
| 张三 | 18 | 12 | 15 | 17 | =SUM(...) |

各列的识别规则如下：

| 列 | 识别方式 | 缺省行为 |
|---|---|---|
| 姓名列 | 表头包含「姓名」「名字」或「学生」 | 取第一列 |
| 题号列 | 表头包含「题」或为纯数字 | 取姓名列与总分列之间的全部列 |
| 总分列 | 表头包含「总分」「总成绩」「总计」或「合计」 | 取最后一列 |
| 核对列 | 总分列之后，表头包含「核对」「核查」「复核」「检查」或「确认」 | 自动新建 |
| 学号列 | 表头包含「学号」「座号」「编号」「考号」或「序号」 | 按名单顺序编号 |

仅支持 `.xlsx` 格式，旧版 `.xls` 请先在 Excel 或 WPS 中另存为 `.xlsx`。执行 `python make_instance.py` 可生成一份空白实例表，其中包含两位同名的「张三」，用于演示重名确认流程。

## 设置

点击右上角「设置」，配置保存至 `config.json`。

| 配置项 | 说明 |
|---|---|
| 识别引擎 | `sense-voice`（默认，整句解码，准确率最高，随程序分发）；`paraformer`（短句响应更快，姓名与分数连读时不易丢字，约 217 MB）；`sherpa`（流式输出，学生名单自动注册为热词）；`vosk`（模型仅 42 MB）；`faster-whisper`（速度较慢，需额外执行 `pip install faster-whisper`） |
| 模型目录 | 引擎下方显示当前模型位置。随程序分发的模型为只读；需下载的引擎可点击「选择…」指定目录，下载与读取均使用该目录。留空表示自动选择 |
| 麦克风 | 默认「自动选择」，每次启动时挑选一个确实有输入信号的设备 |
| 断句停顿 | 一句话说完后停顿多久视为结束。`sherpa` 自带端点检测，此项对其无效，面板中会置灰 |
| 剥离题号前缀 | 念「第一题18分」时仅取 18 |
| 剥离「分」后缀 | 建议保持开启。关闭后连报「3分4分5分」只能取到最后一个数值 |
| 总分写 =SUM() 公式 | 关闭则写入计算好的数值 |
| 核对一致时写 ✓ | 关闭则仅标记不一致的行 |
| 自动保存 | 四选一：总分核对通过后保存（默认）、每填一个分数即保存、每录完一名学生保存、仅在手动点击「保存」时写盘 |
| 录完自动切下一位 | 核对一致后自动选中下一位尚未录完的学生 |
| 按住说话 | 默认关闭，即点击一次开始、再点击一次结束 |
| 提示音 | 默认关闭。启用后，填分、核对通过、核对不一致、未能识别分别对应不同的提示音 |

语音模型默认从 huggingface 下载，访问受限时自动切换镜像；如有自建镜像，可通过环境变量 `HF_ENDPOINT` 指定。

## 设计要点

### 核对是主流程，而非附加功能

语音识别不可能完全准确。与其追求一次识别正确，不如确保错误必然被发现：教师报出自己心算的总分，程序将听到的各题分数求和，两个数值比对，不一致即标红。

```
不一致（报90 算100）
```

核对列会同时写出所报数值，差额一目了然；若仅标注「不一致」，教师仍需回头重算。默认仅在核对通过后写回 Excel，因此文件中的每一行都是核对过的。

### 无法确定时询问，不作猜测

发音冲突的情形很常见：班上有两位「张三」，「刘洋」与「刘阳」难以区分，「掌声」同时接近「张三」与「张伟」。

此类情形一律弹窗由教师点选，而不是选取相似度最高的候选直接填入。选择期间听写自动暂停，因为教师挑选时的自言自语不应被当作指令；选定后，暂存的那句分数会自动补填，无需重念。

判定依据是拼音相似度中首选项与次选项的差距，而非绝对分值。差距过小意味着无法区分，此时就应当询问。

### 仅在确定的范围内自动处理

- 念出「20 号」而班上只有 12 人时明确报错，不推测最接近的人选
- 题号超出范围（仅有 4 题却念了第八题）时忽略并给出说明
- 数值大到不可能是分数（识别将数字连成 `99999999`）时拒绝写入并说明
- 各题均已填满而又报出一个不带题号的分数时，提示补充题号，不推测位置

宁可让教师多说一句，也不让错误的分数无声进入表格。

### 同音误听在解析层纠正

识别结果中「十八分」被听成「时八分」、「七分」被听成「气氛」、「三分」被听成「三粉」属于常态。这类问题不依赖更换模型解决，而由一张源自实际使用记录的同音表与拼音纠错处理：

| 识别结果 | 纠正为 | 依据 |
|---|---|---|
| 时八分 | 18 分 | 同音字表 |
| 气氛 / 三粉 | 7 分 / 3 分 | 同音字表 |
| 第一体 / 第一期 | 第一题 | 题号后缀容错 |
| 掌声 | 张三 | 拼音相似度 |
| 成序题 | 程序题 | 表头拼音纠错 |
| 钟分九十 | 总分 90 | 关键词拼音兜底 |

拼音纠错设有一条硬性边界：叠字不予纠正。噪声与口吃经折叠后会形成「第第」这类叠字，其两个音节完全相同，与任何声母不同、韵母相同的姓名都会算出很高的相似度（didi 与 lisi 为 0.65），而真实误听的相似度最低只有 0.58。两段区间存在重叠，调整阈值无法分离，只能依据结构直接排除。

### 原始表格不被改动

- 首次打开时自动备份至 `backups/`，保留最近 20 份
- 仅写入分数、总分与核对三列，不修改姓名及其他任何内容
- 表头不必位于第一行，总分列不必位于最右侧
- 写回时保留原文件格式；写入失败（例如 Excel 正占用文件）时明确报错，不会静默丢失分数
- 退出前若无法保存，会询问重试、放弃还是留在程序中，而不是直接关闭

### 程序与 Excel 不争夺同一文件

同时打开程序与 Excel 必然导致互相覆盖：Windows 下 Excel 独占锁定文件，程序完全无法写入；macOS 下虽可写入，但 Excel 不会重新读盘，其保存动作会覆盖已填的分数。

因此打开表格前会检测 Excel 是否正占用该文件，并请 Excel 仅关闭这一个工作簿，其中未保存的改动会先行保存，Excel 内的其他文件不受影响。直接结束进程会连带丢失教师正在编辑的其他文件，故不采用。

## 架构

各层职责清晰、依赖单向，核心逻辑可脱离麦克风与图形界面独立测试。

```
录音线程                     主线程
──────────                   ──────────
recorder.py                  ui/main_window.py
  自动增益 / 自适应门槛 / 断句      表格渲染、十字高亮、右键菜单
      │                              │
      │ 音频块                       │ 识别文本
      ▼                              ▼
speech.py                      state.py
  引擎（本地模型）                 状态机：选人 → 填分 → 核对
      │                              │
      │ 文本  ──── 事件队列 ────►     │
                                     ▼
                               parser.py         excel_io.py
                                 中文数字、分数提取     结构识别、写回、备份
                                 姓名匹配、拼音纠错
```

| 模块 | 职责 | 独立分层的原因 |
|---|---|---|
| `parser.py` | 中文数字、分数提取、姓名匹配、拼音纠错 | 纯函数，不涉及 IO。同音表与全部阈值集中于此，可直接以文本驱动测试 |
| `state.py` | 状态机 `idle → scoring → total` | 不依赖 tkinter。语音与键盘共用 `handle_text()` 一个入口 |
| `excel_io.py` | 表结构识别、写回、备份 | 不感知语音的存在。畸形表格的容错逻辑全部收敛在此 |
| `recorder.py` | 录音线程、增益控制、断句 | 不依赖 tkinter，可用替身引擎单独测试线程行为 |
| `speech.py` | 引擎适配，五个引擎共用一套接口 | 更换引擎不影响上层，接口仅 `begin/feed/finalize` 三个方法 |
| `platform_support.py` | 平台差异集中收口 | 界面代码不直接调用 `os.startfile`、不写死字体名、不假设右键键号 |
| `ui/` | 主窗口、对话框、控件、主题 | 设计令牌集中在 `theme.py`，控件内不出现硬编码色值 |

三处关键设计：

**录音线程与主线程仅通过事件队列通信。** 识别引擎并非线程安全，串行化由录音器保证；压力测试中经过 100 轮启停，引擎调用的峰值并发始终为 1。音量事件在主线程的每一轮中只绘制最后一个，逐条重绘会在事件积压时冻结界面。

**平台差异不散落在界面代码中。** 右键键号（Tk 9 在 macOS 上由 Button-2 改为 Button-3）、DPI 感知、中文字体候选、控制台编码，以及请求 Excel 交还文件，全部收敛在 `platform_support.py`，并各自配有针对性测试。

**语音链路上最热的一段被缓存。** 拼音转换与相似度计算均为纯函数，而同一份名单在整节课中被反复比对。加入缓存后，单句处理耗时由 24.1 ms 降至 0.19 ms，状态机整体为 0.12 ms/句，相对语音解码的数百毫秒可忽略不计。

## 开发与测试

```bash
python -m unittest discover tests        # 全部测试
python -m unittest tests.test_accuracy   # 准确率语料
python -m unittest tests.test_docs       # 文档与代码一致性
```

界面冒烟测试需要图形环境，无头环境下自动跳过。

`tests/test_accuracy.py` 是一套准确率语料，内容为教师实际会念出的语句及表格应当变成的样子，覆盖选人、填分、同音误听、核对、连报、切换、噪声、歧义共八类场景。它检验的是「文本到表格」这一段，不含语音识别本身。新增用例只需向 `CASES` 追加一行。

`tests/test_docs.py` 检验本文档与代码是否一致，包括设置项名称、保存模式档数、列识别关键词、打包清单等。文档描述与实现不符时测试失败。

## 发布

发布流程由 GitHub Actions 执行，在 macOS 与 Windows 上分别构建，产出 dmg 与 zip 两个安装包。

- **验证流水线**：在 Actions 页面手动触发，仅执行构建与打包，不创建 Release。由于打包结果依赖各平台环境，正式发版前建议先手动触发一次。
- **正式发版**：推送 `v` 开头的 tag。构建通过后自动创建 Release，并上传两个平台的安装包。

```bash
git tag v1.0.0
git push origin v1.0.0
```

逻辑层测试是构建的硬性前置条件，未通过则不产出安装包；界面冒烟测试不阻断构建。

## 常见问题

**念出姓名后没有反应。** 先确认左下角显示「已就绪」。说话前后各留半秒停顿，过短的音频会被识别为空。

**姓名识别不准。** 弹窗会列出发音相近的候选，点选即可，也可双击单元格直接输入。名单中含生僻字时，`sherpa` 引擎会将学生名单注册为热词，姓名识别更准确。

**分数填错了。** 对同一题重念一次即可覆盖；也可点击「撤销」（⌘Z / Ctrl+Z），或右键该行选择清除整行分数。

**总分核对不一致。** 说明有题目念错或听错。核对列已同时写出两个数值，差额可直接看出。

**完全没有声音。** 点击「帮助 → 麦克风没声音？」，其中按当前系统给出权限设置步骤，并可一键跳转至对应的系统设置页。

**保存失败。** 表格正被 Excel 打开时无法写入。程序在打开表格前会尝试请 Excel 交还该文件；若未能关闭，会提示手动关闭后重试。

**能否一边打开 Excel 一边录入。** 不建议。Excel 不会自动重新读盘，其保存动作会以旧数据覆盖程序写入的分数；Windows 下更会直接锁定文件。建议录入完成后再查看。
